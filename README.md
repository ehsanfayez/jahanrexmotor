# جهانرکسان موتور — Jahanrexan Motor

وب‌سایت شرکتی تک‌صفحه‌ای برای معرفی و برندسازی جهانرکسان موتور در حوزهٔ قطعات و مجموعه‌های خودرویی. سایت فروشگاه اینترنتی نیست و قیمت‌گذاری، سبد خرید یا پرداخت ندارد.

## فناوری‌ها و پیش‌نیازها

- Astro `7.4.2`، TypeScript `7.0.2` و GSAP / ScrollTrigger `3.15.0`
- Tailwind CSS `4.3.3` با افزونهٔ Vite و CSS اختصاصی
- فونت خودمیزبان Vazirmatn و چیدمان فارسی RTL
- Sharp `0.35.5` و PostCSS `8.5.31` برای ابزارهای آماده‌سازی و بررسی

نسخه‌های دقیق در `package-lock.json` ثبت شده‌اند. شرط پروژه در `package.json` برابر **Node.js >=22.23.4** است. آزمون تحویل با Node.js `24.19.0` و npm `11.17.0` انجام شده است.

## نصب

پس از clone، در ریشهٔ پروژه اجرا کنید:

```sh
npm ci
```

از npm و همین lockfile استفاده کنید. برای ساخت، `devDependencies` هم لازم‌اند؛ نصب با `--omit=dev` برای مرحلهٔ build کافی نیست. تنظیم محیطی، حساب سرویس خارجی یا فایل `.env` برای وضعیت فعلی پروژه لازم نیست؛ به همین دلیل `.env.example` ساختگی ایجاد نشده است.

## توسعه

مطابق راهنمای `AGENTS.md`، سرور توسعه را در پس‌زمینه اجرا کنید:

```sh
npm run dev -- --background
npx astro dev status
npx astro dev logs
npx astro dev stop
```

آدرس و پورت واقعی را از خروجی فرمان بخوانید. قبل از اجرای دوباره، وضعیت سرور موجود را بررسی کنید.

## بررسی و ساخت تولیدی

```sh
npm run typecheck
node --experimental-strip-types --test scripts/image-refresh.test.mjs
npm run build
node scripts/verify-production.mjs
npm run preview
```

`typecheck` مسیر importهای محلی و TypeScript را بررسی می‌کند. `verify-production.mjs` پس از build، دارایی‌ها، مشتق‌های تصویر، شماره‌های تماس و نبود ابزار موقت اندازه‌گیری را کنترل می‌کند. `preview` فقط برای مشاهدهٔ محلی خروجی تولیدی است و جایگزین میزبان تولیدی نیست.

بررسی مستقل کامپایل utilityهای Tailwind:

```sh
node scripts/verify-tailwind-utilities.mjs
```

این ابزار fixture موقت می‌سازد، آن را حذف می‌کند و در پایان سایت واقعی را دوباره build می‌کند. اسکریپت‌های بررسی فازهای قدیمی، شواهد همان مرحله هستند و الزاماً آزمون انتشار نسخهٔ فعلی محسوب نمی‌شوند.

## ساختار پروژه

```text
src/components/       اجزای Astro، صحنه‌ها و بخش‌های شرکتی
src/data/             محتوا، مختصات روایت و اندازه‌های تحویل تصویر
src/scripts/          کنترل منو، تایم‌لاین‌های GSAP و cleanup
src/styles/           استایل‌های اختصاصی و tokens.css
src/tailwind.css      ورودی theme و utilityهای Tailwind
src/pages/index.astro صفحهٔ اصلی فارسی
public/images/parts/  تصاویر PNG اصلی
public/images/parts/optimized/  مشتق‌های WebP و manifest.json
public/fonts/         Vazirmatn و مجوز OFL
public/licenses/      اعلان‌های مجوز موردنیاز
scripts/              آماده‌سازی تصویر و ابزارهای QA
docs/                 گزارش‌ها، محدودیت‌ها و مستندات تحویل
astro.config.mjs      تنظیم Astro و افزونهٔ Tailwind/Vite
dist/                 خروجی تولیدی؛ تولیدشده و خارج از Git
```

## سیستم روایت سینمایی

GSAP / ScrollTrigger روایت هیرو، پیشرانه، ترمز و تعلیق، بدنه و روشنایی، کابین و پوشش جامع را کنترل می‌کند. دسکتاپ و موبایل تایم‌لاین‌های مستقل دارند و اسکرول رفت‌وبرگشت حفظ شده است.

در عرض حداقل `1024px` مسیر دسکتاپ و در عرض `320–1023px` مسیر موبایل فعال است؛ هر دو به ارتفاع حداقل `600px` و حالت عادی حرکت نیاز دارند. در `prefers-reduced-motion: reduce` و نمایشگرهای کوتاه، محتوای ثابت و قابل‌دسترسی باقی می‌ماند. تغییر breakpoint، ارتفاع stage، اندازهٔ تصویر یا منطق تایم‌لاین باید همراه با آزمون رفت‌وبرگشت، anchorها و cleanup باشد.

## استایل‌ها

CSS اختصاصی و توکن‌های `src/styles/tokens.css` مبنای طراحی‌اند. Tailwind 4 به‌صورت انتخابی با پیشوند `tw:` استفاده می‌شود؛ فقط theme و utilities وارد می‌شوند و **Preflight غیرفعال است**. ترتیب stylesheetها، فونت Vazirmatn، RTL و resetهای موجود را بدون آزمون رگرسیون تغییر ندهید.

## تصاویر و مجوزها

PNGهای اصلی و WebPهای مشتق‌شده هر دو برای تحویل نگهداری می‌شوند. مشتق‌های موجود برای نصب عادی کافی‌اند. فقط پس از تغییر تصویر اصلی، اجرا کنید:

```sh
npm run prepare:parts
npm run build
node scripts/verify-production.mjs
```

پس‌زمینهٔ استودیو و سدان شفاف دو لایهٔ مستقل‌اند؛ آن‌ها را ادغام یا با تصویر جایگزین نکنید. فهرست دارایی‌ها و وضعیت مجوز در [مستند انتساب](docs/ATTRIBUTIONS.md) آمده است. **پیش از ارسال فایل‌ها به GitHub، حق بازتوزیع تصاویر و نشان تجاری باید تأیید و ثبت شود.** برای کل پروژه مجوز عمومی فرض نشده است.

## استقرار

تنظیم فعلی Astro خروجی **static** در `dist/` تولید می‌کند و adapter سمت سرور ندارد. پس از build، محتوای کامل `dist/` را روی میزبانی فایل‌های استاتیک قرار دهید؛ اجرای Node.js در میزبان نهایی لازم نیست. ارائه‌دهندهٔ استقرار در پروژه تعیین نشده است.

آدرس دارایی‌ها ریشه‌ای است؛ استقرار در زیرمسیر نیازمند تنظیم `base` و بازبینی مسیرهای `/images/` و `/fonts/` است. HTTPS، فشرده‌سازی، cache و headerهای امنیتی باید متناسب با میزبان انتخابی تنظیم و آزمایش شوند. فایل‌های `node_modules/`، فایل‌های محیطی و ابزارهای QA را به‌جای خروجی `dist/` منتشر نکنید.

## محدودیت‌ها و تحویل

- نصب تمیز این ممیزی با `npm ci --offline` از tarballهای کش و با integrity همان lockfile موفق شد؛ تلاش نصب آنلاین در محیط آزمون به‌دلیل `ECONNRESET` ناموفق بود. نیاز به اتصال سالم npm در نصب اولیهٔ یک دستگاه بدون کش باقی است.
- [گزارش فاز ۵.۶.۳](docs/phase-5-6-3.md) شامل اندازه‌گیری‌های **محلی و آزمایشگاهی** است؛ کاهش انتقال ۵۰٫۹٪ دسکتاپ و ۳۴٫۱٪ موبایل تضمین عملکرد روی همهٔ دستگاه‌ها نیست.
- پوشش گوشی واقعی، Safari/WebKit و Firefox کامل نشده است. Lighthouse، INP میدانی و رفتار واقعی نوار مرورگر موبایل اندازه‌گیری نشده‌اند.
- بعد از تغییرات، هیرو و تمام فصل‌ها، پوشش جامع، انتقال به بخش روشن، منو، فوکوس، کاهش حرکت و لینک‌های تماس بررسی شوند.
- شمارهٔ فعلی تماس `tel:09373020028` است؛ تغییر آن نیازمند تأیید محتوایی است.
- گزارش‌ها و تصاویر QA تاریخی حفظ شده‌اند. قبل از تحویل مخزن، دربارهٔ دامنهٔ شواهد همراه تصمیم بگیرید؛ فایل‌های نامطمئن را خودکار حذف نکنید.
- [گزارش آمادگی تحویل فاز ۵.۷](docs/phase-5-7.md) مرجع وضعیت امنیت، نصب تمیز، مجوزها و موارد باز است. این فاز هیچ مخزن، commit یا push ایجاد نمی‌کند؛ عملیات Git متعلق به فاز ۵.۸ و نیازمند دستور جداگانه است.
